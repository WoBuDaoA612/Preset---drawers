# 预设抽屉

给 SillyTavern 的预设加一层你自己定义的「抽屉」分类。

解决的问题：同时用多个 AI 模型游玩时，预设会随模型迭代出新版本。旧版本对应旧模型、新版本对应新模型，全都平铺在一个下拉框里，看不出谁是谁。

## 术语

这几个词含义固定，不随上下文变化：

- **抽屉**：你自己定义的预设分类。一个抽屉里可以放任意多个预设，同一个预设可以同时属于多个抽屉。
- **未分类**：没有归入任何抽屉的预设所在的位置。
- **分组**：给条目打的标记，说明「这条条目属于哪个分组」。分组不是抽屉，与预设归到哪个抽屉无关。
- **条目**：预设里的提示词条目，也就是 AI Response Configuration 面板里列出的那些行。条目只出现在条目列表里，不属于任何抽屉。

## 它做什么

- 把原生预设下拉框**隐藏**（元素本身完整保留，只是看不见），换成抽屉选择器
- 在抽屉面板里按你的分类浏览、搜索、一键切换预设
- 一个预设可以**同时属于多个抽屉**
- 拖拽归类，抽屉内可自定义排序
- 抽屉可折叠收起，折叠状态下依然能接住拖过来的预设
- 抽屉可新建、改名、删除、上下移动
- 「未分类」为空时不显示，不占位置
- **给条目打分组标记**（只打标记，不改动条目顺序）
- **双击（或长按）条目查看 / 编辑**（姓名、身份、触发器、位置、深度、排序、禁止覆盖、提示词等），保存前弹确认框，默认还会先自动备份预设
- **把条目移出一个分组**（条目行尾的移出键），只改标记，条目与预设文件都不动

## 它不做什么

- **抽屉归属与分组标记都不写进预设文件**，只存在扩展设置里，删扩展、清数据都不影响你的预设。
- **本扩展唯一的写盘动作**是编辑条目后点保存，写进去的是条目字段本身，与上面两样无关。那一步有两道拦：确认框 + 自动备份。
- **不接管 ST 的预设机制**。隐藏的下拉框仍是「当前选中哪个预设」的唯一真相，ST 的保存 / 重命名 / 删除 / 角色自动绑定 / 斜杠命令全部照常工作。
- **不动提示词排序**。Prompt Manager 里的条目顺序（`prompt_order`）不会被本扩展改动，编辑条目时也不会。

## 安装

### 方式一：扩展安装器

1. 打开 SillyTavern，进入 **扩展** 标签页
2. 点右上角 **安装扩展**
3. 填入本仓库地址，点安装
4. 刷新页面

### 方式二：手动放置

把整个 `preset-drawers` 文件夹放到：

```
SillyTavern/data/<你的用户名>/extensions/preset-drawers/
```

或者给所有用户安装：

```
SillyTavern/public/scripts/extensions/third-party/preset-drawers/
```

然后刷新页面。

> 文件夹名不要求叫 `preset-drawers`。扩展会从自身模块地址推导所在目录，所以从 Git 地址安装（ST 用仓库名做目录）也能正常加载设置面板。

## 使用

### 归类预设

1. 点预设下拉框原来的位置（现在是一个显示当前预设名的控件），打开抽屉面板
2. 点面板底部 **新建抽屉**，起个名字，比如 `Claude 3.5`
3. 把左边的预设**拖到**抽屉里
4. 同一个预设可以再拖进第二个抽屉，比如 `常用`

移出抽屉：点预设右边的小 **×**，只影响这一个抽屉。

### 调整顺序

把一个抽屉里的预设拖到同抽屉内另一个预设上方，即插入到它前面。

### 折叠抽屉

点抽屉名左边的箭头收起它，点抽屉名本身也一样。搜索时所有抽屉会自动展开，方便直接看到命中项。

折叠状态只保留到页面刷新为止，不写进设置文件。

### 给条目打分组标记

给 Chat Completion 预设里的条目打上分类，长预设里也能一眼分清哪些条目是一伙的。

1. 在 **扩展 → 预设抽屉** 里点「新建分组」，起个名字，比如 `角色定义`
2. 到预设的条目列表（AI Response Configuration 面板里那份），每个条目行右侧有一个分组标记，**点它**就会弹出勾选菜单，勾上分组即可（一个条目可以同时属于多个分组）
3. 勾好之后，列表里会在该组**第一个成员的位置**出现一条分组横幅，成员行左侧亮一条竖线，行尾显示所属分组名

设置面板里能直接看到分组的内容：每个分组是一张**可折叠**的卡片，展开后按**预设**分块，列出哪些预设里有条目挂在这个分组下、每个预设下有哪几个条目（条目行只显示名字和字数，正文双击打开看）。预设那一层也能折叠。卡片右上角的输入框改组名（回车或点到别处生效，改成已有名字会**合并**两个分组），垃圾桶删除分组。

横幅上的操作：

- 点箭头或组名 → 折叠 / 展开这一组（按原位置隐藏成员）
- 点漏斗图标 → **只看这一组**，其余条目暂时隐藏
- 点垃圾桶 → 删除这个分组（只清标记，条目本身毫发无损）

> **这一层只打标记，不动顺序。** 条目的排列顺序就是发给模型的提示词顺序，所以本扩展**绝不**改动它——分组横幅是插在条目之间的旁挂元素，条目的先后关系一个字节都不变。代价是：同一组的条目**不会挨在一起**，它们只按原顺序显示各自的标记。

### 编辑条目

在 **扩展 → 预设抽屉 → 预设抽屉管理** 里选好 API、点「打开」进入条目列表。**双击**（触摸设备可**长按**）任意一条条目打开编辑框（只在这个列表里，不影响酒馆自己的条目列表）：

- 编辑框是浏览器原生 `<dialog>`，居中、遮罩、Esc 关闭都由浏览器负责，写法与酒馆自带弹窗一致；**点遮罩也能关**
- 可改：姓名、身份、触发器、位置（相对 / 聊天中）、深度、排序、禁止覆盖、提示词
- 字段与选项全部照抄酒馆原生那套（含 `locales/zh-cn.json` 里的中文文案）
- **触发器**是 select2 下拉，点开才列选项；不选任何一项表示不限制生成类型
- 位置选「相对」时深度与排序隐藏；**禁止覆盖**只在 `main` 与 `jailbreak` 这两个标识上出现，与酒馆原生一致
- 点**保存**先弹确认框，确认后才写进预设文件；**一个字段都没改过时直接关掉弹窗**，不备份、不确认、不写盘。打开「保存条目前自动备份预设」时，写盘前还会把改动前的预设存一份
- 保存成功后会重绘酒馆自己的条目列表，改完的条目名不必刷新页面才看得见
- 条目行尾的垃圾桶是**移出键**：把这个条目从当前分组里移出，**只动标记，条目本身和预设文件一个字节都不改**，同样先弹确认框

**注意：这个功能会真正修改预设文件。** 两个与写盘有关的说明：

- 改的是**当前正在使用**的预设时，扩展会同时更新运行时的提示词，免得切个预设、改动又变回去
- 改**别的**预设时，写盘用内存里那份预设快照；如果那个预设在别处还有没保存的改动，先在酒馆里保存一次它

`marker` 条目（`Chat History`、`Chat Examples` 这类）的正文由酒馆在运行时拼出来，预设文件里没有可编辑的文本，所以正文框是锁住的——这跟酒馆原生编辑框的行为一致。

### 备份

开着「保存条目前自动备份预设」时，**每次真正有改动、要写盘之前**，才会把改动前的预设存一份到酒馆的 `user/files` 目录，文件名形如 `pd-backup-20260928-114500-03152.json`（上传接口只收 ASCII 文件名，所以预设名不进文件名，改记在设置面板的清单里）。

备份清单在设置面板**最下面单独一块**，按预设名分组，**默认收起**：展开后每个预设名下列出各自的备份，可直接下载或删除。最多保留 20 份，更旧的连文件一起清掉。

### 管理抽屉

点面板右上角的齿轮进入管理模式：

- 直接改输入框里的名字，**回车**或**点到别处**（包括关闭面板）都会保存，选择器上的名字即时跟着变。改成已存在的名字会自动**合并**两个抽屉
- 上下箭头调抽屉顺序
- 垃圾桶删除整个抽屉，抽屉里的预设会回到「未分类」

## 设置项

在 SillyTavern 的 **扩展** 面板里找到「预设抽屉」，自上而下依次是：

1. 总开关与三个勾选框
2. **预设提示词条目分组管理**：新建分组，或展开已有分组查看它挂了哪些预设的哪些条目
3. **预设抽屉管理**：选一个 API 再点「打开」，进入条目列表（也就是编辑条目的地方，见上文）
4. **清空所有抽屉数据**
5. **备份**：默认折叠的清单

| 设置 | 说明 |
|---|---|
| 启用预设抽屉 | 总开关 |
| 替换原生预设下拉框样式 | 勾选后用抽屉选择器顶替原生下拉框的位置；关掉就恢复原生外观，只在旁边留一个抽屉按钮。**排查问题时用这个** |
| 启用预设提示词条目分组 | 勾选后才给预设里的提示词条目标记分组；关掉则条目列表恢复原样，已建的分组不丢，重新勾上即回来 |
| 保存条目前自动备份预设 | 往预设文件里写之前，先把改动前的预设存一份到 `user/files`，面板里能看到、下载、删除。默认开启；关掉后保存就直接写，没有备份 |
| 清空所有抽屉数据 | 重置，预设文件不受影响 |

## 已知边界

- **分组不会改变条目顺序**（这是刻意的，见上文），所以同一组的条目不会在列表里聚到一起。
- 条目的归属按**条目标识**记录。自定义条目的标识每个预设各不相同，所以标记只对那份预设生效；ST 的内建条目（如 `Main`、`Chat History`）标识**在所有预设里都一样**，因此标记一个内建条目后，条目列表里每个预设下面都会列出它——这是「它确实在所有预设里都存在」的如实反映。
- 分组只对 **Chat Completion** 预设有效（酒馆里只有它使用条目管理器）。
- 条目分组的折叠 / 只看这一组状态只保留到页面刷新为止。
- **高级格式化面板里的模板预设**（上下文模板 / instruct 模板 / 系统提示 / 推理模板）**不在覆盖范围内**。它们不走 ST 统一的预设管理器，是各自独立实现的下拉框，接入需要另一套逻辑。
- 「未分类」区域的预设顺序沿用 ST 原生顺序，不支持自定义排序。
- 抽屉的折叠状态存在页面内存里，刷新页面会复位。
- **编辑条目会写预设文件，且不可撤销**，所以那一步有两道拦：确认框 + 自动备份。关掉自动备份就只剩确认框。
- 条目编辑同样只覆盖 **Chat Completion** 预设（与分组同源）。
- 条目列表里的条目顺序取自预设计算里 `character_id` 为 100001 的那份 `prompt_order`（Chat Completion 实际使用的那份）。老预设里可能还留着一份 `character_id` 为 100000 的旧顺序（往往只有十来个内建条目），本扩展不采用它。
- 「移出」只去掉分组标记，条目本身仍在预设里；移出之后它就不再出现在这个分组的条目列表里，重新打标即可回来。
- 备份文件放在酒馆的 `user/files`（数据银行用的也是这个目录）。扩展只在自己清单内保留 20 份，超出会删掉对应的旧文件，不会碰目录里的其它文件。
- 条目列表里的条目数量取决于预设本身：内建条目（`Main`、`Chat History` 等）会在每个预设下各列一遍。
- 卸载时**默认不会**清除扩展数据。扩展设置（抽屉归属、分组标记、备份清单）存在酒馆全局的 `extension_settings` 里，删掉扩展目录清不掉它。想在删除时一并清干净，勾上删除确认框里的「**同时清理扩展数据**」勾选框；勾了之后扩展数据（含备份文件）连同扩展目录一起清掉。这个勾选框是酒馆核心代码的文案，中文语言包漏翻了这一条（英文原文 `Also clean up extension data`），所以界面上显示的仍是英文。设置面板里的「清空所有抽屉数据」只清抽屉归属，分组标记和备份清单不受影响。

## 兼容性说明

本扩展通过 `SillyTavern.getContext()` 访问 ST 内部接口（`extensionSettings` / `saveSettingsDebounced` / `eventSource` / `eventTypes` / `getPresetManager` / `renderExtensionTemplateAsync` / `getRequestHeaders` / `Popup` / `chatCompletionSettings`），不修改 ST 源码。

保存完还会 `import('/scripts/openai.js')` 取出 `promptManager` 重绘酒馆自己的条目列表；这一步拿不到就跳过（改动已经写盘，只是列表要等下次渲染才更新），不会反过来挡住保存。

写预设文件走的是 ST 自己的 `POST /api/presets/save`（与酒馆「保存预设」同一条通道），备份走 `POST /api/files/upload`，删除备份走 `POST /api/files/delete`。都带 CSRF 头。

条目编辑框依赖浏览器原生的 `<dialog>`（酒馆自己的弹窗也用它），需要一个支持 `showModal()` 与 `::backdrop` 的浏览器；Safari 需在 15.4 以上。

如果 ST 后续版本调整了预设下拉框的 `data-preset-manager-for` 属性，本扩展会探测不到对应面板并自动跳过，不会报错。

## 更新日志

### 1.1.1

- 修复条目行错位。新版前端的酒馆（如 TauriTavern）把条目行改成了 4 列网格，每个元素的位置由 `grid-column` 钉死。扩展此前改动过这几列的宽度和数量，两处对不上——条目名被塞进 80px 的窄列截断、分组标记被挤走。现在**逐字保留酒馆原有的列，只在末尾追加一列**放分组标记：酒馆写死的列号不受影响，标记也有了自己的一列，不会被网格自动流挤到第二行。旧版前端是 3 列结构，另配一份定义与手柄兜底，仅在检测到旧版行结构时生效（旧版靠 `:has()` 给条目行定位，不支持该选择器的内核下拖拽手柄会跑飞）。
- 条目行的分组标记去掉「分组」占位文字，只保留标签图标（悬停仍显示提示）。
